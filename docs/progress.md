Checkout idempotency increment: checkout issues a database-backed key bound to the customer/guest cart and reviewed cart/coupon snapshot. The attempt row is locked before cart/stock and commits its order relationship, request/receipt hashes, and completion marker in the order transaction. Same-key retries recover the original order before current-cart or availability checks, preserving later cart items/coupons and avoiding duplicate stock reservations, usage counters, receipts, and confirmation sends. Changed committed details/receipt bytes conflict; foreign owners are rejected. Draft validation/rollback failures remain correctable; cart changes require review, while price refresh leaves the draft incomplete. Coupon edits update the key and total together. One private path per attempt recovers interrupted writes; commit-state checks prevent deleting committed receipts after response failures. Completed markers survive order deletion and cannot create another order. Customer cart scope explicitly uses the web guard. Empty-cart checkout reload recovers the original result, including after ordering closes. See [Checkout operations](CHECKOUT_OPERATIONS.md).
